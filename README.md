# Бот Лісового архіву

Telegram-бот для звірів: вони надсилають документи з порадами, а інші ставлять питання й отримують
відповідь **лише з надісланих документів** — із зазначенням, з якого документа взято пораду, хто його
надіслав і коли (щоб знати, кому дякувати).

Python 3.12 · aiogram 3 · Groq (безкоштовний рівень) · SQLite FTS5 · Docker

## Запуск (однією командою)

```bash
cp .env.example .env          # впишіть TELEGRAM_BOT_TOKEN і GROQ_API_KEY
docker compose up --build
```

| Змінна | Призначення |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен від @BotFather (обов'язково) |
| `GROQ_API_KEY` | ключ з console.groq.com (обов'язково) |
| `GROQ_MODEL` | текстова модель, за замовчуванням `llama-3.3-70b-versatile` |
| `GROQ_VISION_MODEL` | модель для читання сканів, за замовчуванням `meta-llama/llama-4-scout-17b-16e-instruct` |
| `GOOGLE_API_KEY`, `DRIVE_FOLDER_ID` | необов'язково: докачувати «Лісовий архів» з Google Диска при старті |

«Лісовий архів» (78 документів) лежить у `data/archive/`, тож бот знає його від самого початку й без ключів
Google. База зберігається в `./storage` і переживає перезапуск; скани з архіву розпізнаються лише раз.

Перевірка без Telegram: `docker compose run --rm bot python -m app.cli "Які внески в рукавичці Під дубом?"`

## Вимоги Мишки-шкряботушки та як їх виконано

| Вимога | Рішення |
|---|---|
| Звірі надсилають документи, інші питають | Документи — PDF, Word (.docx), txt; питання — звичайним текстом |
| Бот завжди називає джерело | Джерела формує сам код, а не модель: у відповіді лишаються лише ті документи, на які модель послалась номером `[N]`. Відповідь без жодного підтвердженого джерела не показується |
| Показувати не лише назву, а й хто надіслав і коли | `Назва — надіслав(ла) Ім'я, дата (для: місце)`. Для архіву: «Лісовий архів, автор невідомий» |
| Справжнє ім'я автора питати при першому надсиланні | Питається один раз, зберігається; анонімності немає (про неї не домовлялися) |
| Будь-хто може надсилати, без адмінів і схвалення | Ролей немає. Єдиний крок — підтвердження автором того, що бот зрозумів |
| Незрозуміло, для кого порада → перепитати автора | Якщо місце не визначено, бот показує кнопки з усіма місцями. Схожа назва → питає, чи це нова версія |
| Новіший варіант того самого документа для того самого місця замінює старий | Ключ заміни — (тип документа, місце). Стара версія стає неактивною й зникає з відповідей |
| Стандартні документи — з теки «Лісовий архів», знати з самого початку | Завантажуються при першому запуску; теж можуть замінюватися |
| «Місце» = весь ліс / хвойна чи листяна частина / біля річки / рукавичка | 8 рукавичок, 3 частини лісу, див. `app/knowledge/forest_map.py`. **Під вербою** — листяний ліс і річка; **На узліссі** — жодна частина |
| Суперечливі поради → конкретніша важливіша | У контексті кожен документ має позначений рівень; промпт: рукавичка > частина лісу > весь ліс. Загальну можна згадати додатково з джерелом. Рівні однакові й суперечать — показуються обидві |
| Лише особисті повідомлення | Групові чати ігноруються |
| Українська мова | Усі тексти та промпти українською |
| Немає відповіді в документах | Чесне «В наданих порадах я цього не знайшов» (моє рішення) |

### Рішення, яких не було в розмові

- **Скани.** У «Лісовому архіві» 19 із 38 PDF — це картинки без тексту. Скани читає vision-модель Groq, запасний
  варіант — Tesseract (`ukr`). Автор бачить розпізнаний текст і підтверджує його перед збереженням.
  Tesseract на цих сканах помиляється («Зайчик» → «Вайчик»), тому він лише запасний.
- **Місце часто вказане лише в шапці тексту**, а не в назві файлу («Для мешканців біля річки»), тому класифікатор
  дивиться і на назву, і на перші 400 символів.
- **Питання без місця.** Якщо відповідь залежить від рукавички («Які внески?»), бот питає, про яку мова, і
  об'єднує відповідь із початковим питанням. Загальні питання («Що робити при пожежі?») відповідаються одразу.
- **Видалення.** Автор може прибрати власний документ через `/mydocs` (без заміни). Архівні документи видалити
  не можна.
- **Захист від ін'єкцій.** Будь-хто може надіслати документ, тому промпт трактує їхній текст лише як дані.

## Як це працює

```
документ → читання (PDF/DOCX/TXT, скан → OCR) → тип + місце (назва, шапка) → підтвердження автором
        → SQLite (+ FTS5 trigram) ; заміна старої версії

питання → місце (рукавичка/частина лісу) → потрібні рівні (Під вербою = рукавичка + листяний + річка + ліс)
        → відбір документів → Groq (JSON: found + answer з [N]) → код додає «Джерела»
```

Пошук — FTS5 з триграмами: коротка основа слова знаходить різні відмінки («внески» ↔ «внесок»). Для кількох
сотень односторінкових документів векторний пошук не потрібен.

## Структура

```
app/main.py            запуск: база → архів (у фоні) → polling
app/bot/               хендлери (питання, завантаження, /mydocs), тексти
app/ingest/            читання файлів, OCR, завантаження архіву, Google Drive
app/knowledge/         карта лісу, класифікація, сховище, заміна версій, пошук
app/llm/               клієнт Groq, промпт і складання відповіді з джерелами
data/archive/          «Лісовий архів» (78 файлів)
tests/                 39 тестів (pytest)
```

## Тести

```bash
pip install -r requirements-dev.txt && pytest
```

Покривають: класифікацію всіх 78 файлів архіву, розпізнавання місця (Під вербою, На узліссі), заміну версій,
пошук з відмінками, повні діалоги через диспетчер aiogram (Telegram і Groq підмінені).

## Обмеження

- Безкоштовний рівень Groq має ліміти запитів і токенів; клієнт повторює запит при 429, у контекст іде не більше
  8 документів. Назви моделей винесені в змінні оточення на випадок, якщо Groq їх змінить.
- Стан діалогу завантаження (FSM) зберігається в пам'яті: при перезапуску бота незавершене підтвердження
  треба почати заново. Збережені документи та імена не втрачаються.
